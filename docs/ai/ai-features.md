# AI Features

OrderSystem contains two AI-related features:

```text
AI Knowledge Assistant
AI Order Process Explainer
```

Both features use OpenAI and Supabase pgvector.

The AI functionality is supporting functionality only.

It does not control order state and does not replace SQL Server as the source of truth.

## AI Knowledge Assistant

The AI Knowledge Assistant answers technical questions based on indexed documentation.

It uses Retrieval-Augmented Generation.

## RAG Flow

```text
User question
  ↓
OpenAI embedding generation
  ↓
Supabase pgvector similarity search
  ↓
Relevant documentation chunks
  ↓
OpenAI chat completion
  ↓
AI answer with sources
```

## Documentation Ingestion Flow

```text
knowledge-sources.json
  ↓
Source seeding
  ↓
Supabase knowledge_sources table
  ↓
Documentation ingestion
  ↓
HTML extraction
  ↓
Text chunking
  ↓
OpenAI embeddings
  ↓
Supabase knowledge_documents table
```

## Knowledge Sources

Knowledge sources are versioned in the project through:

```text
Infrastructure/Supabase/KnowledgeSources/knowledge-sources.json
```

This file defines which documentation sources should be indexed.

During startup, configured sources are seeded into Supabase.

## Supabase Tables

The RAG feature uses these Supabase tables:

```text
knowledge_sources
knowledge_documents
```

### knowledge_sources

Stores configured documentation sources.

### knowledge_documents

Stores chunked and embedded documentation content.

## Vector Search

When the user asks a question, the system:

```text
creates an embedding for the question
  ↓
searches similar documentation chunks in Supabase
  ↓
uses the best matching chunks as context
```

The final answer is generated by OpenAI using the retrieved context.

## AI Knowledge Endpoint

```text
POST /ai/knowledge/ask
```

Example request:

```json
{
  "question": "What are Azure Service Bus dead-letter queues used for?"
}
```

The response contains:

- generated answer
- source documents used during retrieval

## Manual Knowledge Document Endpoint

```text
POST /ai/knowledge/documents
```

This endpoint is admin-only.

It can be used to manually add knowledge documents.

## AI Order Process Explainer

The AI Order Process Explainer explains the current state and lifecycle of a specific order.

It combines:

```text
SQL order data
  +
status history
  +
email notification history
  +
retrieved documentation context
```

## Important Rule

SQL Server is the source of truth.

The AI must not invent order state from documentation.

Actual order data comes from SQL Server.

Documentation/vector search is only supporting context.

## Order Explanation Flow

```text
OrderId + user question
  ↓
SQL order lookup
  ↓
Access control check
  ↓
Status history lookup
  ↓
Email notification history lookup
  ↓
Question embedding
  ↓
Supabase vector search
  ↓
Structured SQL context + documentation context
  ↓
OpenAI answer generation
  ↓
AI order explanation
```

## SQL Context Used

The order explainer can use:

- order id
- customer data
- current order status
- total amount
- currency
- description
- created timestamp
- updated timestamp
- cancellation reason
- tracking number
- fulfillment timestamps
- status history
- email notification history

## Documentation Context Used

Vector search can retrieve documentation about:

- order statuses
- valid transitions
- payment behavior
- fulfillment workflow
- email notification behavior
- messaging behavior
- dead-letter behavior

## Access Control

The AI order explainer must follow the same authorization rules as the normal order endpoints.

```text
User  → can explain only their own orders
Admin → can explain all orders
```

The AI endpoint must not expose order data that the current user could not access through the normal API.

## Answer Style

The answer should adapt to the question.

```text
narrow question  → short direct answer
status question  → current status only
email question   → email history explanation
process question → lifecycle explanation
failure question → relevant failure or waiting reason
```

The feature should not always return a long lifecycle explanation.

It should answer the actual user question.

## Main Order Explanation Endpoint

```text
POST /ai/orders/{orderId}/explain
```

Example request:

```json
{
  "question": "What is the current status of this order?"
}
```

Example broader request:

```json
{
  "question": "Explain the full lifecycle of this order and whether any manual action is needed."
}
```
